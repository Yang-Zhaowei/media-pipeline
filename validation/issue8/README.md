# Issue #8 experiment — instruction policy vs generation boundaries

**Status: experiment *preparation* only. No production code was changed, no GPU
run was executed, and Issue #8 is not claimed resolved.**

This package compares how **generation boundaries** (short, one-sentence units
vs long, multi-sentence units) and the **instruction policy** (non-empty vs
empty top-level `instruct`) affect narration continuity, using the existing
production `render_speech` entry point unchanged.

The hypothesis is deliberately **not assumed**: empty instruction and long
generation units are *not* presumed better. The design fixes the common
paragraph-boundary `pause_after_ms` so the *same physical junction* is compared
across schemes; only the number of original sentences generated per unit and
the presence of the shared instruction vary.

## The four cases

All four concatenate to the **identical 155-code-point text, same order**
(see `shared_text_sha256` in `MANIFEST.json`). The two common paragraph
junctions (after sentence 3 and after sentence 6) carry a fixed `600 ms` pause
in **every** case; every other junction in the short plan carries `0 ms`.

| Case | Boundaries | `instruct` | Units |
| --- | --- | --- | --- |
| **A** | short (one sentence / unit) | original non-empty | 9 |
| **B** | short | empty | 9 |
| **C** | long (one paragraph / unit, ≥2 sentences) | original non-empty | 3 |
| **D** | long | empty | 3 |

Same-junction comparison (from the junction mapping):

- Paragraph 1 junction = after `sp-03` (short) and after `pg-1` (long), both `600 ms`.
- Paragraph 2 junction = after `sp-06` (short) and after `pg-2` (long), both `600 ms`.

The frozen manuscript was **newly authored** because no original failure
manuscript or original instruction existed in the repository. **It is new
experiment material and cannot alone be used to claim reproduction of the
original problem.**

## Commands (run on ai-core)

### 1. Dry run — validate all inputs, show the plan, load no model

```shell
python validation/issue8/run.py --dry-run --case A,B,C,D --repeat 3
```

### 2. Single-group trial — one case, e.g. long + empty instruct

```shell
python validation/issue8/run.py --case D --repeat 1
```

### 3. Full run — all four cases, three fresh renders each

```shell
python validation/issue8/run.py --case A,B,C,D --repeat 3
```

Each case/repeat writes to a **fresh** directory `<root>/<case>-<NN>` and
refuses to overwrite an existing one. A failed run is recorded and never
retried; the driver exits **non-zero** if any run fails. Renders are executed
sequentially — never concurrently.

Large WAV artifacts land under `EXPERIMENT_RESULT_ROOT` (gitignored); they are
not committed to the repository.

## Evidence produced under the result root

- `summary.json` — commit SHA, clean-tree flag, interpreter/model/device ids,
  per-run status, errors, per-unit frame counts, whole-episode duration, and
  SHA-256 of final WAV/SRT/timeline/report and of the original + cleaned WAVs.
- `scheme_mapping.json` — case→unit mapping and the sentence↔junction mapping.
- `listening_ids.json` — anonymous listening number per run (no path/text/commit embedded).
- `scorecard.csv` / `scorecard.md` — human scoring table, **all score cells blank**.

Scoring dimensions (scale: `0` continuous/natural, `1` minor change/deliverable,
`2` needs regeneration, `3` unusable):

```
same_sentence_junction  cross_unit_junction  in_segment_sustained_drift
missed_duplicate_misread  subtitle_sync
```

No automatic PASS is filled in; human listening and subtitle-sync acceptance
remain to be completed by a person.

## Verification done (CPU, no CUDA)

Run on `main` at HEAD `44bdbb6` (working tree clean for this experiment):

```shell
.venv/Scripts/python.exe -m pytest tests/test_issue8_experiment.py -o addopts="" -q
.venv/Scripts/python.exe -m pytest -o addopts="-ra" -q
```

Results:

- **17/17** new driver tests pass. Coverage: four-case text identity and order;
  short-internal-pause-zero / common-boundary-pause-fixed; long ≥2 units;
  junction mapping aligns the common boundaries; `--dry-run` imports **no**
  `torch`/`qwen_tts`/`qwen_aligner` module and creates no output directory;
  dry-run aborts on a preflight failure; `execute` refuses an existing directory,
  keeps every failure visible, uses a fresh output directory per repeat, and
  returns non-zero on failure; the driver never imports `threading`/
  `multiprocessing`; blank scorecard written.
- **Full regression: 306 passed, 6 skipped** (289 original + 17 new). The 6
  skips are the gated GPU integration tests; they are **not** GPU evidence.
