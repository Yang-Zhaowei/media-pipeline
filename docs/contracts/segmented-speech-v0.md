# Segmented Speech v0 — PR Feature Contract v1

状态：用户确认的下一 PR 范围；本文是实施与审查的共同依据，不代表功能已经实现。
规划基线：`main` 的 `795c4b6`。开始实施或审查时仍须核对实际仓库状态。
建议 PR 标题：`feat: render pre-segmented scripts to WAV and SRT`。

## C1. 目标与边界

Agent 提供已分段稿件、音色及风格指令；一次同步 Python 调用自动生成完整 WAV、
对应 SRT 和可核对的总时间轴。正常路径不需要阶段间人工放行。

复用现有 Production TTS、Production Alignment、Audio Postprocess、Caption Compiler。
只补输入边界、两套环境的专用顺序调用、逐段结果记录及确定性汇总。
这需要生产代码，不是扩展测试 harness；生产路径不得导入 `tests/` 或 `experiments/`。

## C2. 唯一公开调用入口

```python
result = render_speech(
    script_path,
    output_dir,
    tts_python=...,
    alignment_python=...,
    tts_model=...,
    alignment_model=...,
    max_segment_chars=...,
)
```

上述为拟定公开函数及参数；返回类型的具体类名不强制，但必须满足 C6。
模型和解释器路径显式传入，不硬编码 ai-core 路径。保留现有两个运行环境。
只增加这个同步 Python 入口；不增加公开 CLI、HTTP、MCP 或服务进程。
专用内部子进程的启动方式是实现细节，不扩展为公开调用产品。

## C3. 稿件格式与预检

输入为 UTF-8 JSON：

```json
{
  "language": "Chinese",
  "speaker": "Uncle_Fu",
  "instruct": "自然、清晰、克制，语速适中。",
  "segments": [
    {"id": "intro-01", "text": "欢迎收听本期节目。", "pause_after_ms": 300},
    {"id": "chapter-01-01", "text": "今天我们讨论一个具体问题。"}
  ]
}
```

- `language`、`speaker` 为必填非空字符串；`instruct` 为字符串，默认空字符串。
- `segments` 为非空数组；每段必须有唯一、非空字符串 `id` 和有效字符串 `text`。
- `text` 原样传给三个生产阶段，不 strip 后改写、不规范化数字、不添加标点。
  空白或纯标点文本按已有 `has_alignable_content` 规则拒绝。
- 数组顺序就是节目顺序。每项恰好一次 TTS 请求，不根据换行或标点重新分段。
- `pause_after_ms` 是非负整数，布尔值不算整数，默认 0。它表示后处理音频之后
  额外插入的静音。最后一段也可有尾部静音。它不是两段语音之间的完整停顿长度。
- 拒绝未知字段，避免音色、时间参数拼写错误被静默忽略。
- `max_segment_chars` 是必填正整数（非布尔值），以 Python `len(text)` 的 Unicode
  码点数计，包含标点和空白。它是调用方的输入预算，不是已验证的模型最大长度。
- 超长只拒绝，报告段 ID、实际长度与限制。禁止截断、自动拆句、跳过、改稿。
- 所有可静态发现的问题在加载模型前汇总报告。不能完成静态预检时不启动 GPU。
- 模型支持的音色/语言可在加载后使用现有适配器检查；不宣称静态预检能保证模型支持。
- `id` 是标识，不作为未经处理的路径；中间文件使用内部生成的安全名称。
- 输出目录必须尚不存在，拒绝覆盖已有运行及输入；预检不能修改输入文件或 fixtures。

## C4. 模型生命周期与各段独立性

正常成功运行采用两次顺序模型会话：

1. 加载 TTS 一次，按顺序合成全部段落。每段即时落盘并验证 mono PCM16、正采样率、
   正帧数和元数据一致性。完成后退出 TTS 进程。
2. 加载 Aligner 一次，对各段各自的原始 WAV 和原稿进行对齐，保存逐段结果。
3. 使用现有纯处理代码完成逐段后处理、字幕编译和最终汇总。

禁止逐段启动/卸载模型、在失败段上立即切换回 TTS、同时常驻两个模型作为前提。
内部顺序处理即可，不要求张量 batch、并行、GPU 队列或特定吞吐率。
每段局部时间轴从本段音频零点开始，后一段对齐不依赖前一段的结果或时长。
CPU 处理中保留已有默认 padding/fade 和字幕配置，本 PR 不增加这些参数面板。

## C5. 失败语义

| 条件 | 行为 |
| --- | --- |
| 输入预检失败 | 一次性报告可发现的输入错误；不启动模型 |
| TTS 合成失败或生成无效 WAV | 停止；保留已生成文件；不进入整期汇总 |
| 单段 Alignment 返回后，确定性校验发现无效时间戳或文本映射等问题 | 记录该段 `alignment_failed`，继续下一段 |
| 单段后处理/字幕确定性校验失败 | 记录段 ID、具体阶段与原因，其他可处理段继续 |
| 模型加载、CUDA、子进程、磁盘 I/O 或未分类异常 | 停止相应运行；保留已有结果，不冒充可隔离的段落错误 |
| 全部段处理完成且全部通过 | 校验最终产物后，发布完整结果 |
| 存在可隔离的段失败 | 返回 `incomplete` 和逐段报告，不发布完整 final |

只能按明确的错误类别继续处理，禁止宽泛捕获所有异常后 `continue`。
子进程须保留段 ID、阶段和原始原因；不能把本来可隔离的结果校验错误全部变为
子进程整体失败，也不能把模型运行时故障误标为普通对齐失败。

Alignment 是时间定位器，不是朗读质量裁判。报告“对齐失败”，不推断“音频读错”。
不自动重试、重新合成、回退到估算字幕、删除失败段或导出多个“成功总段”。
保留中间文件不等于自动缓存/恢复：本 PR 不提供 `resume`、段落修复或复用入口。

## C6. 结果与完成标记

`render_speech` 在正常阶段处理完毕后返回结果对象：

- `status`：`complete` 或 `incomplete`；
- `run_dir`、`report_path`；
- 完整成功时的 `wav_path`、`srt_path`、`timeline_path`，否则为 `None`。

预检和运行级故障抛出明确异常；运行已开始时异常包含运行目录/可用报告位置。
磁盘不可写时只能尽力保存报告，不能伪造报告成功或掩盖原始异常。

建议固定输出布局：

```text
<output_dir>/
  request.json          原始请求副本
  report.json           配置、段 ID/顺序、已完成阶段、产物路径、错误
  segments/...          逐段 raw WAV、原始/调整后 alignment、成功段 cleaned WAV
  final/                仅在整期校验通过后发布
    final.wav
    final.srt
    timeline.json
```

报告标识 `running/complete/incomplete/failed`，不把正在运行当作成功。记录内容和
相对路径应足够定位结果；不需要数据库、跨运行缓存键或通用任务状态机。
先在同一输出目录内的临时 final 目录生成并重新读取校验，再发布 `final/`；
完成标记最后写入。消费者必须同时检查完成标记，不因文件存在就认为成功。
明确处理崩溃留下的临时/未完成产物，不自动覆盖或续跑旧目录。

## C7. 总时间轴与产物完整性

以各段**后处理后的实际 WAV 帧数**累计，所有段须同采样率、mono PCM16；不一致则失败，
不隐式重采样。只拼接 WAV 数据帧并重新写有效文件头，不能拼接整个 WAV 文件字节。

设共同采样率为 R，第 i 段 cleaned WAV 帧数为 N_i：

```text
G_i = half_up(pause_after_ms_i * R / 1000)  # 实际插入的零值 PCM 帧数
O_i = sum(N_j + G_j for j < i)             # 整数帧累计
全局字幕时间 = 本段 cleaned 音频局部字幕时间 + O_i / R
最终总帧数 = sum(N_i + G_i)
```

- 保留各 cleaned 段的全部样本和顺序；不进行第二次裁剪、变速、交叉淡化或重新淡入淡出。
- 保留原始 TTS WAV，不被 Alignment、后处理或拼接覆盖。
- 局部字幕由原稿和本段调整后 alignment 生成。不跨输入段重新组合文字或字幕。
- 移动未舍入的 caption 时间，最后统一调用既有 SRT 渲染；不得累计已舍入的 SRT
  时长，也不得把最后一个字幕结束时间当作下一段起点。
- 最终字幕编号连续、非空、开始早于结束、非负、不重叠（相接允许）。毫秒量化造成
  零时长字幕时明确失败，不擅自扩展时间戳。文字按现有空白语义完整保留，标点不改写。
- 内部局部/全局时间在对应音频范围内，浮点容差遵循已有 1e-6 秒语义；SRT 最终
  half-up 舍入相对精确音频边界允许最多 0.5 ms 加浮点容差。不能以此容忍累计漂移。
- `timeline.json` 至少包含共同采样率、总帧数，以及各段 ID、start_frame、
  audio_frames、pause_after_frames。秒值如提供，必须由这些整数派生。
- 最终 WAV 帧数/采样率/格式、SRT 实际文件内容、timeline 必须重新读取核对。
- 有失败段时其最终裁剪长度尚未确定，不能用 raw 时长冒充 cleaned 时长；不输出
  被标为完整的全局时间轴。成功后统一计算即可，后面的局部 alignment 无需重算。

## C8. 必须执行的验证

CPU（无需 CUDA）：

1. 全部预检规则、未知字段、重复 ID、非字符串、bool 数值、空/纯标点/超长段；
   证明失败发生在模型加载前，且不改动输入。
2. N 段只加载一次 TTS 和一次 Aligner；一个明确的 alignment 校验失败后仍处理
   后段；运行时故障则停止。可用 CPU 假实现检查生命周期和协议，不冒充 GPU 证据。
3. 三段以上、不等长、非零裁剪、额外静音/尾部静音、相接字幕和帧数准确性。
4. 足够多且长度不同的短段，暴露按段毫秒舍入导致的累计漂移；验证全局时间来自整数帧。
5. 采样率/格式不一致、错误方向偏移、SRT 舍入边界/零时长、原 WAV 不变、最终文件
   回读一致性、失败段不能消失后仍返回完整成功。
6. 已存在目录拒绝、运行失败没有有效完成标记、最终产物发布失败的行为。
7. 完整既有 CPU 回归保持通过；不可修改已有 regression fixtures。

ai-core：

- 在干净、明确提交的实现上，使用公开新接口和新稿件（至少三段、不等长、包含额外
  停顿）完成 fresh TTS -> Alignment -> Postprocess -> captions -> 整期 WAV/SRT。
- 记录输入、配置、各阶段加载/处理日志、逐段及整期帧数、产物路径/哈希、测试结果。
  证明每阶段模型只加载一次，而不是靠估计运行时间判断。
- 显式请求 GPU 验证时，配置不完整或运行失败必须失败，不能 skip 后声称通过。
- 人工试听最终节目、段落接缝和字幕同步。过程中不增加逐阶段人工审批。
- 无 ai-core 条件时可完成实现和 CPU 验证，但 PR 保持未完成验收；旧 PR #5 的
  单 utterance 证据不能替代本次多段接口验证。

## C9. 非目标与停止条件

不做 HTML、视频、NLE、ASR 质检、自动断句/改稿、声音克隆、多角色、精确速度/音高、
响度母带处理、公开 CLI/MCP/HTTP、环境合并、常驻服务、队列、通用编排、缓存/恢复、
自动重试/修复或部分节目交付。不重构已经完成的 v0 组件以预留未来扩展。

停止条件：一次调用自动完成已分段稿件；每阶段模型只加载一次；整期产物的文字、
音频和总时间轴一致；局部校验失败可定位且不阻塞其他独立段的计算，但禁止不完整
节目被发布为成功；CPU、真实 ai-core 多段验证及人工验收均有明确证据。
